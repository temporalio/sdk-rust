With `WorkflowErrorType::Nondeterminism` in `workflow_failure_errors`, a workflow that fails a task during replay with the SDK's `[TMPRL1100]` nondeterministic future error now fails once, with that error. Previously, the next event in history could replace that error with another one, or put a second terminal command in the same completion, which the server refused, so the workflow task timed out and later attempts failed it without failing the workflow.
With `WorkflowErrorType::Nondeterminism` in `workflow_failure_errors`, a nondeterminism error that Core finds during replay now fails the workflow with only Core's fail command. Previously, the completion also had the workflow's `CompleteWorkflowExecution` from the replayed task, which the server refused.
