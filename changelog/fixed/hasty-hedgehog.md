With `WorkflowErrorType::Nondeterminism` in `workflow_failure_errors`, a nondeterminism error that the SDK reports while a local activity result is still pending fails the workflow once, with that error. Before, the workflow could fail with another error, or the completion could have two fail commands.
With `WorkflowErrorType::Nondeterminism` in `workflow_failure_errors`, a nondeterminism error in a workflow task that only delivers an update to a cached workflow fails the workflow once, and the server aborts the update. Before, the worker process aborted with a stack overflow.
With `WorkflowErrorType::Nondeterminism` in `workflow_failure_errors`, the completion of an activation that fails for nondeterminism returns in a workflow task that reads a history newer than itself, such as a sticky task that timed out while it waited for a cache slot. Before, it waited for a history page that Core never fetched.
A workflow task that reads a history newer than itself, such as a sticky task that timed out while it waited for a cache slot, replays every task of that history. Before, when the last whole task of the history pages that Core had fetched had no commands, Core could lose that task and fail the workflow task with "History is out of order".
